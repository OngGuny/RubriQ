# QWK (Quadratic Weighted Kappa)

## 한 줄

**순서가 있는 점수에서, 기계 채점이 사람 채점과 얼마나 일치하는지 재는 지표.**
자동 채점 분야의 사실상 표준. 이 프로젝트의 주 지표다.

---

## 왜 정확도로는 안 되는가

정답 3점인 에세이를 두 채점기가 각각 이렇게 예측했다:

| | 예측 | 정확도 판정 |
|---|---|---|
| 채점기 A | 4점 | ❌ 오답 |
| 채점기 B | 1점 | ❌ 오답 |

정확도로는 **둘 다 똑같이 틀렸다.** 하지만 A는 거의 맞혔고 B는 크게 빗나갔다.

점수는 **순서형(ordinal)** 이다. 1 < 2 < 3 < 4 < 5라는 순서와 거리가 의미를 갖는다.
정확도는 이 정보를 통째로 버린다. 그래서 QWK를 쓴다.

QWK는 **틀린 거리를 제곱해서 벌한다.**
- 1칸 빗나감 → 벌점 1
- 2칸 빗나감 → 벌점 4
- 4칸 빗나감 → 벌점 16

멀리 빗나갈수록 훨씬 세게 깎인다. 이게 이름의 **Quadratic(2차)** 이다.

---

## Kappa는 뭔가 — "우연히 맞힌 것"을 빼는 장치

단순히 "평균 오차"를 재면 안 되는 이유가 있다.

**모든 에세이에 무조건 3점을 주는 채점기**를 생각해보자.
실제 점수가 3점 근처에 몰려 있으면 이 바보 채점기도 평균 오차가 작게 나온다.
아무것도 안 했는데 점수가 좋다.

Kappa는 이걸 막는다:

```
        관측된 불일치
κ = 1 - ──────────────
        우연히 기대되는 불일치
```

- 사람 수준으로 일치 → **1.0**
- 우연히 찍은 것과 같은 수준 → **0.0**
- 우연보다도 못함 → **음수**

그래서 상수 채점기는 0.0이 나온다.
`tests/unit/test_metrics.py::test_constant_prediction_against_varied_truth_is_zero`가 이걸 고정해 뒀다.

**Weighted**는 앞의 "거리를 벌한다"를 kappa에 넣었다는 뜻이다.
합치면 — **Quadratic(거리 제곱으로) Weighted(가중한) Kappa(우연 보정 일치도).**

---

## 값을 어떻게 읽나

| QWK | 해석 |
|---|---|
| 1.0 | 완벽 일치 |
| 0.8~ | 매우 높음 |
| 0.6~0.8 | 실무에서 쓸 만함 |
| 0.4~0.6 | 약함 |
| 0.0 | 찍는 것과 같음 |
| 음수 | 찍느니만 못함 |

**주의**: 이 구간은 관례이고 절대 기준이 아니다. 진짜 기준은
**사람끼리의 일치도(IAA)** 다. 사람끼리 0.7인 과제면 기계 0.7은 사람 수준이다.

> 우리는 아직 IAA를 모른다. 그래서 회귀 임계치 0.60에 근거가 없다.
> Q8 답변의 약점란에 적어뒀고, 베이스라인 실측 후 **상대 기준**("베이스라인 대비 몇 % 하락")으로 바꿀 계획이다.

## 직접 확인한 것들 (`eval/metrics.py`)

sklearn `cohen_kappa_score(weights="quadratic")`를 실제로 돌려보고 알아낸 것:

| 입력 | 결과 | 뜻 |
|---|---|---|
| 완벽 예측 | 1.0 | 정상 |
| 완전 반대 | -1.0 | 정상 |
| 정답 다양, 예측 상수 | 0.0 | 바보 채점기를 제대로 잡는다 |
| **정답도 상수, 예측도 상수** | **nan** | ⚠️ 위험 |
| 빈 입력 | 예외 | 정상 |

### nan이 왜 위험한가

정답이 전부 3점이면 "우연히 기대되는 불일치"가 0이 된다. 0으로 나누게 되니 nan이다.
**측정할 수 없는 상태**이지 성능이 나쁜 게 아니다.

문제는 nan이 비교 연산에서 조용히 행동한다는 것:

```python
float("nan") >= 0.6  # False
float("nan") < 0.6  # False   ← 둘 다 False!
```

`assert qwk >= threshold`로 쓰면 fail 하니 다행이지만,
`assert not (qwk < threshold)`처럼 부정형으로 쓰면 **게이트가 조용히 통과한다.**

> **게이트가 침묵하는 것은 게이트가 없는 것보다 나쁘다.** 있다고 믿게 만들기 때문이다.

그래서 `DegenerateGoldenSet` 예외로 올리고, 리포트에서 측정 불가는 `None`으로 둔다.
`0.0`으로 뭉개면 "나쁜 성능"과 구별할 수 없다.

### 라벨을 넘기는 이유

`cohen_kappa_score(..., labels=[1,2,3,4,5])`에서 `labels`를 넘긴다.
실측 결과 **값 자체는 안 변한다** (분자·분모가 같은 배율로 스케일되기 때문).
그래도 넘기는 이유는 **점수 범위를 벗어난 값을 조기에 잡기 위해서**다.
값 보정이 아니라 검증 장치다.

## 이 프로젝트에서 쓰이는 방식

**항목별로 따로 계산한다.** 6개 항목 각각 QWK를 내고 평균도 낸다.

총점 하나만 보면 어느 축이 무너졌는지 모른다.
Grammar가 폭락하고 Vocabulary가 올라 평균이 그대로일 수도 있다.

```
eval/harness.py:evaluate()          → 항목별 QWK 계산
              :check_regression()   → 항목별 + 평균 모두 임계치 검사
                                       위반은 모아서 한 번에 보고
```

`tests/unit/test_harness.py::test_gate_names_the_broken_dimension`이
"위반 메시지에 무너진 항목 이름이 들어가는가"를 확인한다.

## 함정: 0.5점 라벨

ELLIPSE 원본 점수는 **0.5 단위**(1.0, 1.5, ..., 5.0)인데 QWK는 정수 라벨을 전제한다.

정답만 반올림하고 예측은 처음부터 정수라 **오차가 비대칭**으로 들어간다.
2.5점 에세이를 모델이 2로 예측하면 실제 오차는 0.5인데 지표는 1로 계산한다.

대응: 정수 점수만 가진 부분집합으로 QWK를 한 번 더 계산해 **민감도**를 본다.
두 값이 크게 벌어지면 반올림이 지표를 왜곡하고 있다는 뜻이다.
> `docs/01-루브릭.md` 「반올림 정책」에 적혀 있다.

## 한 줄 요약

> QWK는 **"얼마나 빗나갔는지"와 "찍어서 맞힌 건 아닌지"를 동시에 보는 일치도**다.
> 그리고 계산할 수 없을 때 조용히 nan을 뱉으므로, 그걸 잡아내는 게 구현의 절반이다.
