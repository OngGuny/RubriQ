# 앵커 에세이와 few-shot

## 한 줄

**앵커**: 각 점수대의 대표 답안.
**few-shot**: 그 대표 답안을 프롬프트에 예시로 넣어주는 것.

---

## 문제: 서술어만으론 부족하다

루브릭에 이렇게 적혀 있다:

> **Grammar 3점** — 오류가 눈에 띄나 전반적 이해는 가능하다

'눈에 띈다'가 몇 개인가? 6문장에 3개? 5개? 10개?
'전반적 이해가 가능하다'의 경계는 어디인가?

서술어는 **말로 된 기준**이라 필연적으로 모호하다.
아무리 정교하게 써도 사람마다, 호출마다 해석이 흔들린다.
→ 같은 에세이를 다시 채점하면 다른 점수가 나온다 (**일관성 σ가 커진다**)

---

## 해결: 실물을 보여준다

실제 채점 연수에서 하는 방식이 이렇다. 서술어만 주지 않고 **답안 실물**을 같이 준다.

```
이게 Grammar 5점짜리입니다:  [에세이 A 전문]
이게 3점짜리입니다:          [에세이 B 전문]
이게 1점짜리입니다:          [에세이 C 전문]

자, 이제 이 답안은 몇 점입니까?
```

'눈에 띄는 오류'가 뭔지 **말로 정의할 필요가 없어진다.** 보면 안다.
이 대표 답안들을 **앵커(anchor, 닻)** 라고 한다. 점수대를 붙잡아 고정한다는 뜻이다.

> 설계 문서 §1: "루브릭 점수는 상대 기준이다. 앵커를 few-shot으로 붙이면 채점 분산이 줄어든다."

---

## few-shot이란

LLM에게 **예시를 몇 개 보여주고** 작업시키는 방식.

| 방식 | 프롬프트 | |
|---|---|---|
| **zero-shot** | "이 에세이를 채점해" | 예시 0개 |
| **few-shot** | "이건 5점, 이건 3점, 이건 1점. 그럼 이건?" | 예시 몇 개 |

`shot` = 예시 하나. few-shot은 "예시 몇 개짜리"라는 뜻이다.
모델을 재학습(파인튜닝)하는 게 아니라 **프롬프트 안에서만** 가르치는 것이라
비용이 거의 안 들고 즉시 바꿀 수 있다.

> 설계 문서 §6이 파인튜닝을 범위 밖으로 둔 이유가 이것이다 —
> 골든셋 50건 규모에서는 파인튜닝보다 프롬프트·앵커 튜닝의 효율이 훨씬 높다.

---

## 어떤 앵커를 고를 것인가 — 여기서 검색이 등장한다

앵커를 아무거나 넣으면 안 된다.

채점 대상이 **환경 오염에 대한 논설문**인데 앵커가 **가족 소개글**이면
"이런 글이 3점이구나"가 잘 전달되지 않는다. 주제도 길이도 다르기 때문이다.

**비슷한 에세이의 앵커를 골라 넣어야 한다.** 그래서:

```
채점할 에세이
   → 임베딩(벡터로 변환)
      → pgvector에서 유사한 앵커 검색
         → 점수대별로 골라 프롬프트에 삽입
            → 채점
```

이게 `retrieve_anchors` 도구이고, 설계 문서가 말하는
"기존 pgvector 벡터 검색 경험을 재사용한다"의 실체다.

---

## 대가: 토큰

앵커는 **에세이 전문**이다. 3개만 넣어도 프롬프트가 길어진다.

```
루브릭 정의 (고정, 길다)
앵커 3개    (에세이 전문 × 3, 길다)
────────────────────────────  ← 여기까지 매 호출 반복
채점할 에세이 (가변)
```

게다가 이 프로젝트는 **항목별로 따로 호출**한다 (후광 효과 때문).
6번 호출 × 매번 긴 앞부분 = 비용이 6배로 뛴다.

### 그래서 프롬프트 캐싱

고정된 앞부분(루브릭 + 앵커)을 **캐시**해두면 반복 전송 비용이 줄어든다.
그러려면 프롬프트를 이렇게 짜야 한다:

```
[고정 블록: 루브릭, 앵커]   ← 캐시 히트 구간. 절대 안 바뀜
[가변 블록: 채점할 에세이]  ← 뒤로 몰아야 한다
```

가변 부분이 앞에 끼면 그 뒤가 전부 캐시 미스가 된다.
> 핵심: 캐시 히트를 위해 **가변 부분을 뒤로 몰아 배치**하는
> 프롬프트 구조 설계가 선행돼야 한다. (ADR 003)

**분리 호출(비쌈) → 캐싱(상쇄)** 이 한 쌍으로 묶여 있다는 게 이 설계의 핵심이다.

---

## 아직 안 정한 것

- 앵커를 몇 개 넣을 것인가 (3개? 5개? 항목마다 다르게?)
- 점수대별로 하나씩 다 넣을지, 유사한 것 위주로 넣을지
- 앵커를 넣었을 때 일관성 σ가 실제로 줄어드는지 → **측정해야 안다**

> 앵커 없이/있이 각각 골든셋을 돌려 σ와 QWK를 비교하는 게 T1 작업이다.
> "앵커가 분산을 줄인다"는 지금은 **가설**이지 측정이 아니다.

---

## 한 줄 요약

> 앵커는 **말로 설명 안 되는 기준을 실물로 보여주는 것**이고,
> few-shot은 그걸 프롬프트에 넣는 방법이다. 대가는 토큰이고, 상쇄 수단은 캐싱이다.
