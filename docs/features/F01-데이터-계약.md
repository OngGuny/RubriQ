## 문제

LLM은 계약을 어긴다. 6개 항목 중 5개만 채점하고, 점수 범위를 벗어나고,
근거를 달라고 해도 빈 배열을 준다. **이게 조용히 통과하면 지표가 거짓말을 한다.**

## 계약

```
Essay        essay_id · text · grade_level? · task_type? · prompt?
DimensionScore  dimension · score(1~5) · rationale · evidence[≥1]
GradingResult   essay_id · scores[6개 정확히] · needs_human_review · review_reason?
                prompt_version · model_name
```

## 설계

스키마 레벨에서 **거부**한다. 사후 검사가 아니라 생성 시점 차단이다.

| 규칙 | 근거 |
|---|---|
| 6개 항목이 정확히 한 번씩 | 누락·중복이 지표를 왜곡한다 |
| `evidence` 최소 1개 | 근거 없는 점수는 채점이 아니라 추측이다 |
| `needs_human_review` → `review_reason` 필수 | 이유 없이 넘기면 받는 사람이 할 게 없다 |
| `Evidence.span` 길이 = `quote` 길이 | 안 맞으면 둘 중 하나가 거짓이다 |

## 핵심 결정 — 근거 검증은 스키마 밖에 둔다

인용이 **원문에 실재하는지**는 essay 텍스트가 필요해 validator로 못 넣는다.
`ungrounded_evidence(result, essay_text)`로 분리했다. 스키마 안에서 닫히지 않는
검증이 있다는 걸 숨기지 않고 함수 이름으로 드러낸다.

공백만 정규화해 비교한다. 줄바꿈 차이로 오탐이 나면 **검사 자체를 못 믿게 된다.**

## 실패 모드

| 상황 | 처리 |
|---|---|
| 항목 누락/중복 | `ValidationError` — 채점 실패로 집계 |
| 점수 범위 밖 | `GradingError` — 관측 후 실패 처리 |
| 인용이 원문에 없음 | 점수는 유지, `needs_human_review` 플래그 |

**할루시네이션된 근거에도 점수를 버리지 않는다.** 근거가 부실해도 점수 자체는
맞을 수 있고, 그 판단은 사람이 하는 게 맞다.
