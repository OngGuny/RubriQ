# F04. 프롬프트 레지스트리 · 캐시 경계

| | |
|---|---|
| 상태 | **구현됨** (Langfuse 등록 미완) |
| 단계 | T0 |
| 코드 | `src/rubriq/prompts/registry.py` · `templates/scoring_v1.md` · 테스트 16건 |
| 의존 | 없음 |
| 관련 | ADR 003 |

## 문제

두 가지가 겹쳐 있다.

1. **버저닝** — 성능 변화를 프롬프트 변경과 연결하려면 어떤 버전이 쓰였는지 남아야 한다.
2. **캐시** — 프롬프트 앞부분이 1바이트라도 다르면 뒤가 전부 캐시 미스다.
   그런데 **캐시 미스는 에러를 내지 않는다.** 조용히 비용만 오른다.

## 계약

```
load_prompt(name, version) -> Prompt
Prompt.system         # 고정부 — 요청 간 바이트 단위로 동일. 캐시 대상
Prompt.user_template  # 가변부 — {{ESSAY}} 슬롯
Prompt.id             # "scoring@v1"
Prompt.fingerprint    # 내용 SHA256 앞 12자
```

## 설계 — 캐시 경계를 파일 포맷으로 강제

```markdown
(루브릭 전문 · 채점 규칙 · 출력 형식)     ← 고정. 캐시 프리픽스
<!-- CACHE_BOUNDARY -->
Score the following essay...
<essay>{{ESSAY}}</essay>                   ← 가변
```

로딩 시점에 검사한다:

| 검사 | 실패 시 |
|---|---|
| 마커가 정확히 1회 | `MalformedPrompt` |
| `{{ESSAY}}`가 user 블록에 존재 | `MalformedPrompt` |
| **`{{ESSAY}}`가 system 블록에 없음** | `MalformedPrompt` — 캐시를 죽이는 대표적 실수 |
| system 블록 비어있지 않음 | `MalformedPrompt` |

## 핵심 결정 1 — 관례가 아니라 포맷으로

"가변 내용은 뒤에 두자"고 문서에 적는 방식은 몇 주 뒤에 지켜지지 않는다.
로딩이 실패하면 반드시 고치게 된다.

## 핵심 결정 2 — 내용 지문을 둔다

버전 문자열을 안 올리고 내용만 고치는 실수가 자주 난다.
그러면 리포트의 "v1"이 서로 다른 두 프롬프트를 가리킨다.
지문이 있으면 결과표에서 그게 드러난다.

## 함정 — 최소 캐시 프리픽스는 모델마다 다르다

| 모델 | 최소 |
|---|---:|
| Claude Opus 5 | 512 토큰 |
| Claude Sonnet 5 / Opus 4.8 | 1024 토큰 |
| **Haiku 4.5** | **4096 토큰** |

**세대 순이 아니다.** 현재 system 블록은 약 900토큰이라
Opus 5에서는 캐시되지만 **Haiku 4.5에서는 조용히 캐시되지 않는다.**
→ F16 모델 라우팅의 비용 계산에 반드시 포함해야 한다.
