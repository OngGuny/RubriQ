# 기능 기획 문서

파이프라인을 17개 기능으로 나눠 각각 기획한 문서.
구현된 것은 "이렇게 만들었고 왜 그랬다", 미구현은 "이렇게 만들 것이다"를 적는다.

각 문서의 형식: **문제 → 계약 → 설계 → 핵심 결정 → 실패 모드 → 측정**

> 설계 전반은 [`docs/00-설계.md`](../00-설계.md), 결정 기록은 [`docs/adr/`](../adr/).

## 기반 — 구현됨

측정 체계를 먼저 세웠다. 채점기보다 지표가 먼저다.

| | 기능 | 한 줄 |
|---|---|---|
| [F01](F01-데이터-계약.md) | 데이터 계약 | LLM이 계약을 어기면 스키마가 거부한다 |
| [F02](F02-평가-지표.md) | 평가 지표 | QWK의 nan을 예외로 올려 게이트 침묵을 막는다 |
| [F03](F03-평가-하네스와-회귀-게이트.md) | 평가 하네스·회귀 게이트 | 성능이 떨어지면 CI가 빨간불이 된다 |
| [F04](F04-프롬프트-레지스트리.md) | 프롬프트 레지스트리 | 캐시 경계를 파일 포맷으로 강제한다 |
| [F05](F05-LLM-클라이언트와-비용계산.md) | LLM 클라이언트·비용 | 관측값을 응답에 실어 나른다 |
| [F06](F06-베이스라인-채점기.md) | 베이스라인 채점기 | 일부러 약하게 만든 비교 대상 |

## 의존 관계

```
F01 데이터 계약 ─────────────────────────┐
F02 지표 → F03 하네스 ←── F07 골든셋      │
                  ↑                      │
F04 프롬프트 → F05 LLM → F06 베이스라인 ──┤
                  │                      │
                  └→ F08 Langfuse        │
                                         ↓
F09 그래프 상태 ← F10 입력게이트          │
      ↓                                  │
   F11 도구 · F12 앵커 → F13 병렬채점 ────┤
                              ↓          │
                        F14 일관성검증    │
                              ↓          │
                        F15 피드백 ───────┘
                              ↓
                   F16 튜닝 · F17 서빙
```

## 관통하는 설계 사슬

```
후광 효과 → 항목 분리 호출(F13) → 호출 6배 → 캐싱으로 상쇄(F04·F16)
                  ↓
           항목 간 모순 발생 → 일관성 검증(F14) → 상한 2회 → human review
```

```
루브릭 서술어는 모호 → 앵커 few-shot(F12) → 프롬프트 3단계화
                                              → 캐시 경계 확장 필요(F04)
```
