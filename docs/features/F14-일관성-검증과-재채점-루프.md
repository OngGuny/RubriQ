# F14. 일관성 검증 · 재채점 루프

| | |
|---|---|
| 상태 | **미구현** |
| 단계 | T1 |
| 예정 코드 | `src/rubriq/graph/nodes/verify.py` · `edges.py` |
| 의존 | F13 항목별 채점 |

## 문제

F13에서 항목을 분리했더니 **오염은 줄었는데 모순이 생긴다.**
각 호출이 서로를 모르기 때문이다.

```
Grammar 5점  (오류가 거의 없다)
Conventions 1점 (표기 규범이 지켜지지 않는다)
```

둘 다 표기 정확성과 관련되는데 4점이 벌어졌다. 하나는 틀렸다.

## 계약

```
입력: scores (6개) · regrade_count
출력: contradictions: list[str]
      → 분기: 재채점 | 통과 | human review
```

## 설계 — 모순 규칙

| 규칙 | 근거 |
|---|---|
| \|Grammar − Conventions\| ≥ 3 | 둘 다 형식 정확성 축 |
| \|Vocabulary − Phraseology\| ≥ 3 | 낱말과 낱말 결합 |
| 전 항목 최대−최소 ≥ 4 | 능력이 그렇게 극단적으로 갈리기 어렵다 |
| 점수와 근거 불일치 | 5점인데 근거가 오류 지적 |

**임계값 3·4는 근거 없는 초기값이다.** 골든셋의 인간 채점 분포를 보고 조정한다 —
사람도 그만큼 벌리는 경우가 흔하면 그건 모순이 아니다.

## 핵심 결정 1 — 루프 상한은 2회

```
모순 감지 → 재채점(해당 항목만) → 다시 검증
  → 여전히 모순 & regrade_count < 2 → 재채점
  → regrade_count ≥ 2 → needs_human_review
```

**수렴 보장이 없다.** 상한이 없으면 latency가 폭발하고 비용이 무한해진다.
상한 2는 임의값이며, **2회로도 안 잡히는 케이스가 몇 %인지 측정**해서 조정한다.

## 핵심 결정 2 — 상한 초과를 실패로 숨기지 않는다

`needs_human_review = True` + `review_reason`에 **어떤 모순이 남았는지** 적어 반환한다.

> 교육 도메인에서는 그럴듯한 오답보다 "모르겠다"가 안전하다.
> 점수를 지어내면 학생이 잘못된 피드백을 받는다.

## 핵심 결정 3 — 전체가 아니라 모순 항목만 재채점한다

6개를 다 다시 돌리면 비용이 또 6배다.
모순에 연루된 항목만 재채점하고, 이번엔 **상대 항목의 점수와 근거를 컨텍스트에 넣는다** —
"Conventions를 1점으로 봤는데 Grammar는 5점이다. 다시 보라."

이건 F13의 '항목 독립' 원칙을 **의도적으로 깨는 지점**이다.
독립은 1차 채점의 원칙이고, 검증 단계에서는 오히려 교차 참조가 필요하다.

## 실패 모드

| 상황 | 처리 |
|---|---|
| 재채점이 점수를 진동시킴 | 상한 2회로 차단, human review |
| 모순 규칙 자체가 오탐 | human review 비율로 감지 — 30% 넘으면 규칙이 잘못된 것 |
| 재채점 호출 실패 | 원래 점수 유지 + human review |

## 측정

| 지표 | 의미 |
|---|---|
| 모순 감지율 | 전체 중 루프가 발동한 비율 |
| 1회/2회 수렴률 | 상한 2가 적절한지 |
| human review 비율 | **30% 넘으면 자동 채점의 의미가 없다** |
| 재채점 전후 QWK | 루프가 실제로 정확도를 올리는가 |

마지막이 핵심이다. **루프가 QWK를 못 올리면 비용만 쓰는 장치다.**
