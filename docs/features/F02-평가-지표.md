## 문제

"좋아졌다"를 숫자로 바꿔야 한다. 그런데 채점 점수는 **순서형(ordinal)** 이라
일반 정확도로는 부족하다 — 3점을 4점으로 본 것과 1점으로 본 건 다른데
정확도는 둘 다 똑같이 오답 처리한다.

## 계약

| 지표 | 함수 | 반환 |
|---|---|---|
| QWK | `quadratic_weighted_kappa` | `float` 또는 `DegenerateGoldenSet` 예외 |
| 인접 정확도 | `adjacent_accuracy(tolerance=1)` | `float` |
| 일관성 σ | `consistency_sigma` | `float` (그룹별 표본 표준편차 평균) |
| 오류 탐지 | `detection_prf` | `PRF` (+ `f_beta(0.5)`) |
| 지연 | `latency_stats` | `LatencyStats(p50, p95, mean, n)` |

## 핵심 결정 1 — nan을 예외로 올린다

sklearn `cohen_kappa_score`는 **정답과 예측이 모두 상수면 nan**을 돌려준다.
nan은 비교 연산에서 조용하다:

```python
float("nan") >= 0.6   # False
float("nan") <  0.6   # False   ← 둘 다 False
```

정방향 assert는 살지만 부정형으로 쓰면 **게이트가 조용히 통과한다.**
그래서 `DegenerateGoldenSet` 예외로 올린다.

> **게이트가 침묵하는 것은 게이트가 없는 것보다 나쁘다.** 있다고 믿게 만들기 때문이다.

## 핵심 결정 2 — 측정 불가는 `None`이지 `0.0`이 아니다

0.0으로 뭉개면 "나쁜 성능"과 "측정 불가"를 구별할 수 없다.
리포트는 `qwk: None` + `qwk_error: "사유"`로 둘을 분리한다.

## 핵심 결정 3 — 오탐을 미탐보다 세게 벌한다

교육 도메인에서는 없는 오류를 지적하면 학생이 잘못 배운다.
F1과 함께 **F0.5**(precision 가중)를 본다.

## 실패 모드

| 상황 | 처리 |
|---|---|
| 정답·예측 모두 상수 | `DegenerateGoldenSet` |
| 점수 범위 밖 값 | `ValueError` (조기 차단) |
| 반복 1회로 σ 요청 | `ValueError` — 1회로 "일관성 측정했다"를 막는다 |

## 측정

손으로 계산 가능한 값과 대조 고정. 순서형 성질(가까운 예측 > 먼 예측)도 테스트로 고정.
