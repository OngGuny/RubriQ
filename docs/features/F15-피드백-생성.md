# F15. 피드백 생성 (Teachers Comment)

| | |
|---|---|
| 상태 | **미구현** |
| 단계 | T2 |
| 예정 코드 | `src/rubriq/graph/nodes/feedback.py` · `prompts/templates/feedback_*.md` |
| 의존 | F13 채점 결과 · F14 검증 |

## 문제

점수만으로는 교사도 학생도 쓸 게 없다.
"Vocabulary 3점"보다 **"어휘는 의미 전달은 되지만 `good`처럼 뭉뚱그린 표현이 반복된다"** 가 쓸모 있다.

그리고 **초등학생에게 할 말과 고등학생에게 할 말이 다르다.**

## 계약

```
입력: scores (6개, 근거 포함) · grade_level · task_type
출력: teacher_comment: str
```

## 설계 — 학년 × 과제유형 프롬프트 체계

```
prompts/templates/
  feedback_elementary_v1.md
  feedback_middle_v1.md
  feedback_high_v1.md
```

| 학년 | 톤 | 초점 |
|---|---|---|
| 초 | 격려 중심, 짧게 | 잘한 것 먼저, 고칠 건 1~2개만 |
| 중 | 구체적 예시 | 패턴 지적 (반복되는 오류 유형) |
| 고 | 분석적 | 다음 단계 학습 방향 제시 |

## 핵심 결정 1 — 점수 근거를 그대로 재사용한다

F13이 이미 항목별 **본문 인용 근거**를 만들었다.
피드백은 그 근거를 문장으로 푸는 작업이다. 새로 분석하지 않는다.
→ 입력이 이미 구조화돼 있어 LLM 1회로 충분하다.

## 핵심 결정 2 — 교사용이지 학생용이 아니다

출력 대상은 **교사**다. 교사가 보고 학생에게 전달할지 판단한다.
그래서:
- 불확실하면 불확실하다고 쓴다
- `needs_human_review`면 **그 사실을 코멘트 맨 앞에 쓴다**
- 학생을 직접 평가하는 단정적 표현을 피한다

## 핵심 결정 3 — 최저 항목을 우선한다

6개를 다 언급하면 초점이 없다. **가장 낮은 2개 + 가장 높은 1개**를 다룬다.
잘한 것 하나는 반드시 넣는다 — 전부 지적만 하면 쓰이지 않는다.

## 실패 모드

| 상황 | 처리 |
|---|---|
| 조기 반환(F10) 케이스 | 점수 없이 "채점 대상 아님" 사유만 |
| human review 케이스 | 코멘트 앞에 검토 필요 표시 |
| 생성 실패 | **점수는 그대로 반환** — 코멘트는 부가 기능이다 |

## 측정 — 자동 지표가 없다

QWK 같은 정량 지표가 없는 유일한 기능이다. 측정 방법:

| 방법 | 한계 |
|---|---|
| 근거 인용의 원문 실재 검증 (F01 재사용) | 형식만 검증 |
| 길이·항목 커버리지 통계 | 품질과 무관 |
| 소수 샘플 수동 검토 | 주관적, 확장 불가 |

**"측정할 수 없는 기능"이라는 걸 인정하고 문서에 적는다.**
정량화할 수 없는 걸 억지로 숫자로 만들지 않는다.
