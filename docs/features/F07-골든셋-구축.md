# F07. 골든셋 구축

| | |
|---|---|
| 상태 | **미구현** — 외부 의존으로 차단됨 |
| 단계 | T0 |
| 예정 코드 | `scripts/build_golden_set.py` → `eval/golden/ellipse-50.jsonl` |
| 의존 | 없음 (Kaggle 인증 필요) |
| 차단 요소 | Kaggle CLI·인증 미설정 |
| 관련 | ADR 001 |

## 문제

측정의 기준점이 없다. 골든셋이 없으면 QWK도 회귀 게이트도 숫자가 안 나온다.
**이 하나가 T0의 나머지 전부를 막고 있다.**

## 계약

```json
{"essay_id": "...", "text": "...", "grade_level": "middle",
 "scores": {"cohesion": 3, "syntax": 2, "vocabulary": 3,
            "phraseology": 2, "grammar": 3, "conventions": 4}}
```

6개 항목이 다 없으면 `load_golden_set`이 **줄 번호와 함께** 거부한다.

## 설계

```
Kaggle ELLIPSE 다운로드
  → 라이선스 확인 → eval/golden/LICENSE.md 기입      ← 먼저 한다
  → 0.5점 라벨을 정수로 반올림 (round-half-up)
  → 점수 분포가 고르도록 층화 추출 50건
  → jsonl 출력 + 정수 전용 부분집합 별도 출력
```

## 핵심 결정 1 — 분포를 보고 뽑는다

골든셋 50건이 전부 3점 근처면 QWK가 정의되지 않는다(`DegenerateGoldenSet`).
**쉬운 에세이만 뽑으면 측정 도구 자체가 망가진다.** 항목별 점수대가 고르게 퍼지도록 층화 추출한다.

## 핵심 결정 2 — 반올림 민감도를 같이 측정한다

ELLIPSE 원본은 **0.5 단위**(1.0~5.0)인데 QWK는 정수 라벨을 전제한다.
정답만 반올림되고 예측은 처음부터 정수라 **오차가 비대칭**으로 들어간다 —
2.5점 에세이를 2로 예측하면 실제 오차는 0.5인데 지표는 1로 계산한다.

대응: **정수 점수만 가진 부분집합**으로 QWK를 한 번 더 계산한다.
두 값이 크게 벌어지면 반올림이 지표를 왜곡하고 있다는 뜻이다.

## 핵심 결정 3 — 루브릭 원본 대조가 첫 작업

데이터를 받으면 **가장 먼저** ELLIPSE 원본 루브릭 서술어를 `docs/01-루브릭.md`와 대조한다.
어긋나면 내 문장이 더 나아 보여도 **원본을 따른다.**

> 낮은 QWK의 원인은 셋이다 — 모델이 못 하거나, 프롬프트가 나쁘거나,
> **애초에 다른 기준으로 채점하고 있거나.** 세 번째를 배제하지 않으면 앞의 둘 튜닝이 무의미하다.

## 라이선스 처리

재배포가 금지되면 원문은 `eval/golden/raw/`(gitignore)에 두고,
커밋되는 건 파생 지표와 익명화 샘플로 한정한다.

## 남은 위험

- **홀드아웃 미분리** — 프롬프트를 골든셋에 맞춰 튜닝하면 그 50건에만 잘하는 채점기가 된다.
- **IAA 미상** — 인간 채점자 간 일치도를 모르면 "QWK 0.6이 좋은 건가"에 답할 수 없다.
