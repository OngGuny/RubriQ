# 루브릭 정의

채점 프롬프트와 골든셋이 공유하는 기준. **이 문서가 프롬프트의 원본**이고,
`src/rubriq/prompts/templates/`의 루브릭 블록은 여기서 파생된다.

> 루브릭이 **무엇인지**는 [`docs/learning/01-루브릭.md`](learning/01-루브릭.md) 참조.
> 이 문서는 개념 설명이 아니라 **우리가 쓸 기준의 확정본**이다.

---

## ⚠️ 이 문서에서 가장 중요한 경고

**아래 서술어는 ELLIPSE 공식 루브릭이 아니라, 내가 조작적으로 정의한(operationalized) 버전이다.**

골든셋의 인간 점수는 ELLIPSE 애너테이터가 **그들의 루브릭**으로 매긴 것이다.
내 루브릭이 그것과 다르면, 그 차이가 QWK 하락으로 나타난다.
그리고 나는 그걸 **모델 성능 문제로 오진하게 된다.**

> 낮은 QWK의 원인은 최소 세 가지다 — 모델이 못 하거나, 프롬프트가 나쁘거나,
> **애초에 다른 기준으로 채점하고 있거나.** 세 번째를 배제하지 않으면 앞의 둘을 튜닝하는 게 무의미하다.

**따라서 골든셋 확보 시 반드시 할 일:**
1. ELLIPSE 원본 루브릭 서술어를 구해 아래 표와 대조한다.
2. 어긋나는 항목은 **원본을 따른다.** 내 문장이 더 마음에 들어도 그렇게 한다.
3. 대조 결과를 이 문서 하단 「원본 대조 기록」에 남긴다.

이 검증을 건너뛰고 나온 QWK는 숫자일 뿐 지표가 아니다.

- 상태: **미검증** (원본 대조 전)
- 다음 작업: 골든셋 확보 시 대조

## 점수 척도

1~5점 정수. 높을수록 능숙하다.

| 점수 | 대략적 의미 |
|---|---|
| 5 | 해당 능력을 일관되게, 자연스럽게 구사한다 |
| 4 | 대체로 능숙하나 부분적으로 흔들린다 |
| 3 | 기본은 되나 오류·어색함이 눈에 띄게 섞인다 |
| 2 | 의미 전달은 되나 오류가 이해를 자주 방해한다 |
| 1 | 해당 능력이 거의 드러나지 않거나 이해를 심하게 방해한다 |

### 반올림 정책 (측정에 직접 영향)

ELLIPSE 원본 점수는 **1.0~5.0을 0.5 단위**로 매긴다. QWK는 정수 라벨을 전제하므로 변환이 필요하다.

- **기본 정책**: 정답 점수를 `round-half-up`으로 정수화한다 (2.5 → 3).
- **문제**: 예측은 처음부터 정수인데 정답만 반올림하므로 **오차가 비대칭**으로 들어간다.
  2.5짜리 에세이를 모델이 2로 예측하면 실제 오차는 0.5인데 지표상 1로 계산된다.
- **대응**: 정수 점수만 가진 부분집합으로 QWK를 한 번 더 계산해 **민감도**를 본다.
  두 값이 크게 벌어지면 반올림이 지표를 왜곡하고 있다는 뜻이므로 정책을 재검토한다.
- 이 민감도 수치를 `docs/results/01-baseline.md`에 같이 기록한다.

> 요점: 0.5 단위 라벨을 정수 지표에 넣을 때 생기는 왜곡을 먼저 측정해,
> **지표 자체를 신뢰할 수 있는지**부터 확인한다.

## 항목별 정의

6개 항목은 **독립적으로** 채점한다. 한 항목의 낮은 점수가 다른 항목을 끌어내리면 안 된다
([설계 문서 §1](00-설계.md) — 항목 간 점수 오염이 분리 호출의 이유다).

### 1. Cohesion — 응집성

문장과 문단이 논리적으로 연결되어 글이 하나의 흐름을 이루는가.
**내용의 좋고 나쁨이 아니라 연결의 문제다.**

| 점수 | 기준 |
|---|---|
| 5 | 문단 구조가 명확하고 전환이 자연스럽다. 연결어가 다양하고 정확하게 쓰인다 |
| 4 | 전반적으로 잘 연결되나 일부 전환이 갑작스럽다 |
| 3 | 기본적인 연결은 있으나 연결어가 단조롭거나(and, but 반복) 문단 구분이 흐리다 |
| 2 | 문장들이 나열에 가깝다. 논리적 순서를 따라가기 어려운 구간이 있다 |
| 1 | 연결이 거의 없어 개별 문장으로 읽힌다 |

### 2. Syntax — 문장 구조

문장을 얼마나 정확하고 다양하게 구성하는가.

| 점수 | 기준 |
|---|---|
| 5 | 단문·복문·복합문을 목적에 맞게 구사한다. 구조적 오류가 거의 없다 |
| 4 | 다양한 구조를 시도하며 대체로 정확하다. 복잡한 문장에서 간혹 흔들린다 |
| 3 | 단순한 구조 위주. 복문 시도 시 오류가 나타난다 |
| 2 | 문장 구조가 단조롭고 어순·구조 오류가 빈번하다 |
| 1 | 문장 경계가 불분명하거나 구조가 무너져 있다 |

### 3. Vocabulary — 어휘

어휘의 범위·정확성·적절성.

| 점수 | 기준 |
|---|---|
| 5 | 폭넓고 정밀한 어휘를 문맥에 맞게 쓴다 |
| 4 | 어휘 범위가 충분하다. 드물게 부정확한 선택이 있다 |
| 3 | 기본 어휘로 의미는 전달하나 반복이 많고 정밀도가 낮다 |
| 2 | 어휘가 제한적이라 표현하려는 의미에 미치지 못한다 |
| 1 | 기초 어휘에 머물러 의미 전달이 자주 실패한다 |

### 4. Phraseology — 관용 표현

연어(collocation)와 관용적 표현을 자연스럽게 쓰는가.
**Vocabulary가 낱말이라면 여기는 낱말의 결합이다.**

| 점수 | 기준 |
|---|---|
| 5 | 연어와 관용 표현이 자연스럽다. 원어민에 가까운 결합을 보인다 |
| 4 | 대체로 자연스러우나 간혹 어색한 결합이 있다 |
| 3 | 익숙한 표현은 정확하나 그 밖에서는 직역투가 나타난다 |
| 2 | 부자연스러운 결합이 잦아 의미 파악에 부담을 준다 |
| 1 | 관용적 결합이 거의 없고 낱말의 나열에 가깝다 |

### 5. Grammar — 문법

시제·일치·관사·전치사 등 문법 규칙의 정확성.

| 점수 | 기준 |
|---|---|
| 5 | 문법 오류가 거의 없다. 있어도 의미에 영향을 주지 않는다 |
| 4 | 오류가 있으나 산발적이고 이해를 방해하지 않는다 |
| 3 | 오류가 눈에 띄나 전반적 이해는 가능하다 |
| 2 | 오류가 빈번해 이해가 자주 끊긴다 |
| 1 | 오류가 지배적이라 의미 파악이 어렵다 |

> **도구 연계**: `grammar_check`(LanguageTool)가 뽑은 오류 목록을 컨텍스트로 넣는다.
> 오류 **개수를 세는 건 도구**가 하고, 그 오류가 이해를 얼마나 방해하는지 **판단은 LLM**이 한다
> ([설계 문서 §1](00-설계.md) — 결정적 도구와 LLM 판단의 역할 분리).

### 6. Conventions — 표기 관습

철자·구두점·대소문자·문단 나누기 등 표기 규범.

| 점수 | 기준 |
|---|---|
| 5 | 표기 오류가 거의 없다 |
| 4 | 사소한 오류가 있으나 가독성에 영향이 없다 |
| 3 | 오류가 눈에 띄지만 읽는 데 지장은 없다 |
| 2 | 오류가 잦아 가독성을 떨어뜨린다 |
| 1 | 표기 규범이 지켜지지 않아 읽기 어렵다 |

## 채점 시 지켜야 할 규칙

프롬프트에 그대로 반영한다.

1. **본문 인용 필수.** 모든 점수에 근거가 되는 본문 구절을 인용한다.
   인용 없는 점수는 스키마가 거부한다 (`DimensionScore.evidence` min_length=1).
   인용은 **원문에 실재해야** 한다 — `ungrounded_evidence()`가 대조한다.
2. **항목 독립.** 다른 항목의 점수를 근거로 삼지 않는다.
   "문법이 나쁘므로 어휘도 낮게" 같은 추론을 금지한다.
3. **분량으로 벌하지 않는다.** 짧다는 이유만으로 감점하지 않는다.
   분량 미달은 사전 라우팅에서 조기 반환으로 처리한다.
4. **주제 적합성은 채점 대상이 아니다.** 6개 항목 모두 *언어 능력* 지표다.
   내용이 과제를 벗어났으면 사전 라우팅에서 분기한다.
5. **ESL 학습자 기준.** 원어민 기준이 아니라 영어 학습자 기준으로 본다.
   L1 간섭에서 오는 어색함을 과도하게 벌하지 않는다.
